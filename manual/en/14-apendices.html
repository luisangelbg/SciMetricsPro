AFile formats

Chapter 3 explains what to export from each database (Table 3.4). This appendix gathers the exact rules: how the app recognizes each file, which field or tag each piece of data comes from, and which columns it understands in an arbitrary table.

A.1 How the app recognizes a file

The app does not trust the extension: it looks at the content of the file first and uses the extension only when the content is not enough. It checks the rules of Table A.1 in that order and keeps the first one that holds; within each format, it decides which database the file comes from by the columns or fields it carries.

Table A.1. The rules for recognizing each file, in the order in which they are checked.
FormatHow it is recognizedWhich database it comes from
Four-character tagged textA line beginning with PMID- among the first lines, or the extension .nbib.Public biomedical index.
Two-letter tagged textAt the beginning, an FN, VR or PT line, and PT, AU or TI tags.Multidisciplinary citation index B.
RISA TY  - line among the first lines, or the extension .ris.Index A if at least half of the records carry N1 notes with “Export Date:” or “Cited By:”; otherwise, RIS of unrecognized origin.
BibTeXAn @type{ entry or the extension .bib or .bibtex.Index A if its entries carry author_keywords, abbrev_source_title, publication_stage or a “Cited by:” note; index B if they carry keywords-plus, times-cited, cited-references, unique-id or research-areas; otherwise, generic BibTeX.
Delimited text (.csv .tsv .txt .tab) and spreadsheets (.xlsx .xls .xlsm .ods)A first line with commas, tabs or semicolons. From a spreadsheet, the first sheet with data is read.By the headers: index A if it carries “Author full names”, “Authors with affiliations” or “EID”, and “Source title” or “Title”; tab-delimited index B if the headers are the tags PT, AU, TI and UT or SO; biomedical index (summary) if it carries “PMID” and “Citation”; otherwise, generic table (Table A.3).

✓Rule · what applies to every file
EncodingUTF-8, with or without a byte order mark, or UTF-16 with the mark. If it is not valid UTF-8, it is read as Latin-1 and a warning asks you to check accented letters.
SeparatorThe one that appears most often outside quotes in the first line, among comma, tab and semicolon; on a tie, the comma. Double quotes protect separators and line breaks.
HeadersThe first row; if it holds a single note (“Exported on …”), the first of the next five rows with at least two columns. Columns are looked up by name, ignoring case and accents, never by position.
Records without a titleThey are skipped, with a warning saying how many.
Repeated fileOne with the same name and size as a file already loaded is skipped.

iNote · the open catalog and the other databases

Searches of the open bibliographic catalog (Section 3.7) do not go through a file: the app receives each work in JSON format and takes the title, year, source, DOI, abstract, the authors with their institutions and countries, the keywords and the topics assigned by the catalog (as index keywords), the citations and the references, which arrive as catalog identifiers. The open scholarly search engine, the linked research database and the regional index are read with the general rules for RIS, BibTeX or tables.

A.3 An arbitrary table

A CSV table or a spreadsheet that does not come from a recognized database is read as a generic table, with the warning Table of unrecognized origin: only columns with usual names were read. The app looks for these headers, ignoring case and accents; the other columns are not used.
